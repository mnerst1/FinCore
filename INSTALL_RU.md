# Установка FinCore · Day 012

## 1. Что понадобится

- Node.js 22.12 или новее; проверено на Node.js 24.21.
- npm (поставляется с Node.js).
- Docker Desktop с Docker Compose и запущенным Docker engine. На Windows включите WSL 2, если его требует Docker Desktop.
- Либо уже установленный PostgreSQL 17+.
- Интернет при первом скачивании зависимостей и образа PostgreSQL. Для работы приложения внешние ключи и облачные сервисы не нужны.

Распакуйте ZIP в удобную папку. Откройте PowerShell **в папке Day-012-FinCore, где находится package.json**.

## 2. Настройте окружение

```powershell
Copy-Item .env.example .env
```

Откройте `.env`. Для обычного локального запуска значения примера подходят. Если меняете пароль базы, измените его **и в POSTGRES_PASSWORD, и внутри DATABASE_URL**. Для символов `@`, `:`, `/`, `#` в пароле URI используйте процентное кодирование.

```dotenv
DATABASE_URL="postgresql://fincore:change-this-local-password@localhost:5432/fincore?schema=public"
POSTGRES_PASSWORD="change-this-local-password"
APP_URL="http://localhost:3000"
UPLOAD_DIR="./uploads"
DEMO_PASSWORD="FinCore-Demo-2026!"
```

`.env` содержит локальные настройки и не входит в Git/ZIP. Приложение не требует AUTH_SECRET: в базе сохраняются хеши случайных токенов сеанса.

## 3. Запустите PostgreSQL

```powershell
docker compose up -d --wait
docker compose ps
```

Контейнер должен иметь статус healthy. База слушает только `127.0.0.1:5432`; данные сохраняются в Docker volume.

Если порт 5432 занят, измените mapping в `docker-compose.yml` на `127.0.0.1:5433:5432` и порт в `DATABASE_URL` на 5433.

Если используете свой PostgreSQL, создайте пользователя и пустую базу, например `fincore`, выдайте пользователю право владения базой, укажите подключение в `DATABASE_URL` и пропустите команды Docker. Миграциям нужны права на создание таблиц и индексов.

## 4. Установите зависимости и создайте схему

```powershell
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
```

`npm ci` использует проверенный lock-файл. Если пакетный менеджер сообщает о заблокированных install scripts, разрешите скрипты Prisma, esbuild и системного resolver в настройках своего менеджера и повторите установку. Не копируйте чужие node_modules.

`db:migrate` применяет сохранённую SQL-миграцию без shadow database. `db:seed` создаёт демо-аккаунт с шестью месяцами операций, счетами, бюджетами, целями, долгами и регулярными платежами. При повторном запуске seed существующий аккаунт не сбрасывается. Собственная регистрация создаёт чистый профиль с категориями.

## 5. Запустите приложение

```powershell
npm run dev
```

Откройте **http://localhost:3000**.

Демо-почта: **demo@fincore.local**. Демо-пароль: **FinCore-Demo-2026!**, если вы не поменяли `DEMO_PASSWORD` перед первым seed.

Не открывайте `http://127.0.0.1:3000`, пока `APP_URL` равен `http://localhost:3000`: защита Origin требует точного совпадения. Если нужен другой адрес, измените APP_URL, перезапустите сервер и используйте именно этот адрес. Пример на порту 3001: APP_URL=`http://localhost:3001`, запуск `npm run dev -- --port 3001`.

Процесс терминала должен оставаться запущенным. Чтобы остановить приложение, нажмите Ctrl+C. Затем при необходимости остановите базу:

```powershell
docker compose down
```

Не добавляйте `-v`, если хотите сохранить данные.

## 6. Рабочая сборка

Остановите dev-процесс перед сборкой в той же папке:

```powershell
npm run build
npm start
```

Вновь откройте http://localhost:3000. База должна работать. Для локального использования HTTPS не требуется; при размещении в интернете нужны HTTPS, корректный APP_URL и отдельные секретные пароли. Без запроса пользователя этот проект нигде не опубликован.

## 7. Регулярные платежи

При открытии приложения и нажатии «Обновить» наступившие платежи проводятся автоматически. Чтобы они проводились при закрытом браузере, добавьте в планировщик Windows ежедневный запуск `npm run recurring` с рабочей папкой проекта. Пример действия планировщика: программа `powershell.exe`, аргументы `-NoProfile -WindowStyle Hidden -Command "npm run recurring"`, Start in — абсолютный путь к Day-012-FinCore. Используйте ту же учётную запись и окружение, в котором работает приложение.

## 8. Экспорт, импорт и резервная копия

В Настройках можно скачать CSV операций или JSON всех финансовых записей с чеками. CSV добавляет строки, JSON восстанавливает профиль. CSV: до 2 МБ и 2000 строк, JSON: до 64 МБ; чеки — до 5 МБ каждый.

Для JSON создайте новый профиль, установите валюту копии **до создания счетов**, затем выполните восстановление. Профиль должен быть без счетов, бюджетов, целей и долгов; существующие категории заменяются. Старые пароли и сеансы не переносятся. В JSON не входят история действий, уведомления и настройки оформления.

Для полной копии экземпляра остановите приложение и планировщик, затем:

```powershell
docker compose exec -T db pg_dump -U fincore -d fincore -Fc -f /tmp/fincore.dump
docker compose cp db:/tmp/fincore.dump ./fincore.dump
Copy-Item ./uploads ./uploads-backup -Recurse
```

Если uploads ещё нет, шаг копирования пропустите. Сохраняйте dump, uploads и конфигурацию вместе в приватном месте. `pg_dump` включает аккаунты и хеши паролей: не публикуйте его.

Восстанавливать полный dump следует в **новую пустую базу**, а не поверх текущих данных:

```powershell
docker compose exec -T db createdb -U fincore fincore_restore
docker compose cp ./fincore.dump db:/tmp/fincore.dump
docker compose exec -T db pg_restore -U fincore -d fincore_restore --no-owner /tmp/fincore.dump
```

Измените имя базы в DATABASE_URL на `fincore_restore`, восстановите uploads из соответствующей копии, затем запустите приложение. Не запускайте seed для восстановления ваших данных.

## 9. Проверки

```powershell
npm run lint
npm run typecheck
npm test
npm run test:integration
npx playwright install chromium
npm run test:e2e
npm run build
```

Интеграционные тесты требуют PostgreSQL с применённой миграцией. Для браузерных тестов нужна демо-запись. Тесты создают собственных пользователей; браузерные тестовые аккаунты остаются в тестовой базе. Лучше использовать отдельную базу. Ручные шаги — TEST_CHECKLIST.md; результаты проверки при подготовке архива — VALIDATION.md.

## Решение проблем

- **Docker не найден:** установите/запустите Docker Desktop или подключите собственный PostgreSQL.
- **P1001 / connection refused:** проверьте `docker compose ps`, порт и DATABASE_URL.
- **Password authentication failed:** пароль в .env не меняет пароль внутри уже существующего volume. Используйте исходный пароль либо измените его в PostgreSQL; не удаляйте volume с нужными данными.
- **Origin rejected:** адрес страницы должен совпадать с APP_URL, включая протокол, hostname и порт. После изменения .env перезапустите приложение.
- **Демо не существует:** выполните `npm run db:seed` в нужной базе.
- **Демо-пароль не изменился:** seed не перезаписывает пользователя; смените пароль через Настройки.
- **Валюта заблокирована:** её можно менять только до создания счетов. Сначала создайте отдельный чистый профиль.
- **Нельзя удалить счёт/категорию:** удалите связанные операции, бюджеты, регулярные правила и дочерние категории. Так сохраняется целостность учёта.
- **JSON слишком большой:** используйте полный PostgreSQL dump + uploads; JSON предназначен для переносимого личного набора данных до 64 МБ.
- **Язык показывает английские подписи:** дополнительные 12 языков имеют частичный перевод; полные — English, Русский, Қазақша.
- **После смены пароля вышло из аккаунта:** это ожидаемо, все сеансы отозваны.
